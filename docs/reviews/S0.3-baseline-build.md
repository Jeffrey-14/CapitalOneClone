# S0.3 — Baseline simulator builds

Date: October 23, 2026.

Status: **IN PROGRESS — builds recorded, pending review. S0.3 remains unchecked.**

## Purpose and limits

A baseline build checks whether Xcode can process the existing source, resolve build dependencies, compile/link as needed, process resources, and assemble an app for the selected simulator destination. It establishes a local build baseline before feature changes.

Compilation does **not** verify app launch, runtime behavior, screen layout, folding behavior, unit/UI tests, accessibility, performance, real-device signing, TestFlight, or CI. No such verification was performed here. These were ordinary incremental Debug builds using existing DerivedData, not clean-checkout or clean builds. In particular, the Duo build reused compiled Swift output.

## Exact tool calls and reproduction

These are Xcode integration tool calls, not shell commands. Execute in this order with the existing CapitalOneClone workspace open:

```text
XcodeSwitchRunDestination({"displayTitle":"iPhone 18 Pro"})
BuildProject({"buildForTesting":false})
GetBuildLog({"severity":"warning"})

# Continue only if the first build succeeded:
XcodeSwitchRunDestination({"displayTitle":"iPhone Duo"})
BuildProject({"buildForTesting":false})
GetBuildLog({"severity":"warning"})

# Restore the original selected destination after collecting the logs:
XcodeSwitchRunDestination({"displayTitle":"iPhone 18 Pro"})
```

All calls above were executed successfully. No shell `xcodebuild build` command was run, and no fabricated shell exit code is reported. BuildProject performs the build through Xcode's build system. To reproduce manually, choose the CapitalOneClone scheme, select each named destination in order, and use Product > Build; inspect each build in the Report navigator before proceeding. Do not use Run or Test as substitutes for the recorded build-only operation.
